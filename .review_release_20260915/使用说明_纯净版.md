# TDA 拓扑预测流水线 · 使用说明（纯净版）

## 0. 关于本包
本包是「自包含」可执行版本：双击 `tda_launcher.exe` 即可运行，**无需安装 Python 或任何第三方依赖**。

包内结构：

| 路径 | 说明 |
|---|---|
| `tda_launcher.exe` | 主程序（GUI 启动器） |
| `_internal/` | 自包含运行时：Python 解释器 + 全部依赖库（numpy / ripser / topp / gudhi / PySide6 等）+ 项目源码 |
| `data/` | 源数据目录（**初始为空**，需自行放入行情 CSV） |
| `runs/` | 实验结果目录（**初始为空**） |
| `config.json` | 运行配置（已使用相对路径，不含任何本机绝对路径） |
| `data_format.txt` | 源数据 CSV 格式说明 |

> 本纯净版**不含任何历史运行数据与本机路径信息**：`config.json` 的 `source_dir` 为相对路径 `./data/stock`，`runs/`、`data/` 均为空目录。

---

## 1. 首次使用前准备
1. 将行情数据 CSV 放入 `data/stock/` 目录（每支股票一个 CSV，列格式见 `data_format.txt`）。
2. （可选）用记事本打开 `config.json` 调整参数：
   - `as_of_date`：数据截止日（`YYYY-MM-DD`）
   - `source_dir`：源数据目录，默认 `./data/stock`（一般无需改）
   - 其余为拓扑 / 匹配 / 预测参数（详见 §3；修改后会在结果目录中自动体现，互不覆盖）
3. 双击 `tda_launcher.exe` 启动。

---

## 2. 结果保存在哪里（核心）
所有计算结果都保存在 **`runs/`** 目录下。目录路径由参数**自动派生**，无需手动指定：

```
runs/
└─ 2024-06-28/                                ← 第 1 级：实验截止日 as_of_date
   └─ data_<数据集指纹>/                      ← 第 2 级：数据集标识
      └─ topo_w60_lb480_mw4_feat4_mrl3.0_permissive__<hash>/   ← 第 3 级：拓扑 / 持续同调参数
         └─ match_d0-1_thrH0{0.08}_H1{0.08}__<hash>/            ← 第 4 级：瓶颈距离匹配参数
            └─ fc_h5__<hash>/                ← 第 5 级：预测跨度（= 一个完整「实验 run」）
               │
               ├─ （中间产物 / 缓存，见 §4.1）
               │
               └─ outputs/                   ← 最终对外结果
                  └─ topk5/                  ← 按 top_k 分目录
                     ├─ metrics.json
                     ├─ report.txt
                     ├─ selected_matches.csv
                     └─ predictions.csv
```

> **关键设计**：改动任意参数 → 自动生成新的子目录，旧结果**不会被覆盖**。这样可以在 `runs/` 下并存多组参数组合，便于横向对比（见 §5）。

---

## 3. 各级目录代表什么

| 层级 | 目录名示例 | 由哪些参数决定 | 含义 |
|---|---|---|---|
| 1 | `2024-06-28` | `as_of_date` | 数据截止日；只用该日及之前的数据 |
| 2 | `data_xxx` | 源数据内容哈希 + 数据相关配置 | 标识「哪一份数据 + 数据质量设置」 |
| 3 | `topo_w60_lb480_mw4_feat4_mrl3.0_permissive__<hash>` | `window_size`、`lookback_trading_days`、`min_windows`、`features`、`max_edge_length`、`max_homology_dimension`、`data_quality_mode` | 点云构造与持续同调定义；**最耗时阶段**的缓存就沉淀在这里 |
| 4 | `match_d0-1_thrH0{0.08}_H1{0.08}__<hash>` | `distance_dimensions`、两个距离阈值、`topology_backend` / 距离算法 | 瓶颈距离匹配参数 |
| 5 | `fc_h5__<hash>` | `forecast_horizon`、距离参数、后端 | 预测跨度（向前预测几个交易日） |

第 3/4/5 级末尾的 `<hash>` 是**参数指纹**：参数不变则目录名稳定 → 自动复用已有缓存（持久图、距离矩阵等），不必重算；参数一变则新建目录、从头计算。

> 第 3 级（`topo_…`）的 `mrl3.0` 即 `max_edge_length=3.0`，`feat4` 即使用 4 个特征，`permissive` 即数据质量模式为宽松。这些参数共同决定「点云长什么样、持续同调算到哪一维」。

## 4. 各目录包含的文件

### 4.1 run 根目录（第 5 级 `fc_h5__<hash>/`）—— 中间产物 / 缓存
（程序内部复用，一般无需直接查看）

| 文件 | 内容 |
|---|---|
| `artifacts.sqlite3` | **主数据库**：存放所有匹配结果、预测结果、各阶段完成状态 |
| `diagrams_h0.npy` / `diagrams_h1.npy`（及其他维度） | 各维度的**持久图**（点云 → 持续同调条形码） |
| `diagram_counts.npy` | 各点云的单形计数 |
| `diagram_index.json` | 点云索引（`cloud_id` → 文件偏移） |
| `diagram_signature.txt` | 拓扑产物签名（用于内容完整性校验、缓存复用判断） |
| `match_pivot_distance_h0.npy` / `h1.npy` | 匹配枢轴距离矩阵 |
| `match_pivot_rows.npy` / `match_pivot_signature.txt` | 枢轴行映射与签名 |
| `.run_instance.log` | 本次运行的结构化日志（按 work_dir 隔离） |
| `.topology_incomplete` / `.match_incomplete` / `.forecast_incomplete` | 某阶段异常中断的告警标记（**正常完成后自动消失**；若残留说明该阶段未跑完） |
| `_mmap_stage_*` / `_pivot_stage_*` | 阶段性临时目录（正常完成后清理） |

### 4.2 `outputs/topk<N>/` —— 最终对外结果（你主要看这里）

| 文件 | 内容 |
|---|---|
| `metrics.json` | 机器可读的评测指标：各预测跨度（`by_horizon`）的 `correct` / `total` / `accuracy`、整体（`overall`）准确率、完整参数快照（`params`）、生成时间 |
| `report.txt` | 人类可读统计报告：参数快照 + 各跨度准确率 + 整体准确率 |
| `selected_matches.csv` | 相似匹配明细。列：`target_id`, `similar_id`, `rank`, `distance_dim0`, `distance_dim1`, `qualified_count` |
| `predictions.csv` | 预测明细（最细粒度）。列：`target_id`, `horizon`, `target_date`, `actual_difference`, `actual_direction`, `predicted_direction`, `vote_up`, `vote_count`, `correct` |

> `predictions.csv` 每一行 = 一个目标点云在某预测跨度上的「实际涨跌方向 vs 预测方向、投票情况、是否正确」。对比准确率、排查误判都从这里看。

## 5. 对比功能（功能二 · 产物横评）
GUI「对比选中产物」会在独立终端调用 `compare_runs.py`，**自动扫描** `runs/**/outputs/(topk<N>/)metrics.json`，把不同参数组合的预测结果横向排成一张表（含排名、整体 / 各跨度准确率、Δ 差值）。

- 在 GUI「产物」页选中任意层级的目录即可对比：单个 run、多个 run、甚至整个日期目录。
- 选中目录会自动归一到正确的扫描根；跨日期多选则自动退化为 `runs/` 全量横评。

---

## 6. 注意事项
- **纯净版不含数据**，首次运行前务必把 CSV 放入 `data/stock/`。
- `config.json` 使用相对路径，整套目录可整体复制到任何其他机器直接运行（无需 Python 环境）。
- `runs/` 可整体删除后重跑（会重新计算）；`data/` 内容变动会改变第 2 级 `data_` 指纹，自动新建目录。
- 同一 `run` 目录**禁止并发运行**（单实例锁），否则报 `SQLITE_BUSY`。
- 改参数不会覆盖旧结果，而是新建子目录——这是设计使然，便于参数横评。
- **已知限制**：`distance_dimensions` 含高维（如 H9）时，对点数较多的点云持续同调开销极大（组合数爆炸），可能导致长时间无进展；如非必要建议控制在 H1 / H2。
